# Android: локальное приложение

Android-клиент работает самостоятельно: сервер NutriFlow, Docker и запущенный компьютер ему не нужны. Это выбранный пользователем режим **локальных профилей**, не облачные аккаунты. Авторизации по email, переноса между телефонами и синхронизации пока нет.

## Установка

1. Скачайте `NutriFlow-debug.apk` из успешного workflow **Android APK**. Артефакты GitHub хранятся семь дней; сохраните APK отдельно.
2. Перенесите сам APK на телефон и откройте его. Если Android запросит разрешение установки, разрешите установку именно для приложения, которым открываете файл; после установки разрешение можно отключить.
3. Откройте NutriFlow и создайте локальный профиль. Затем откройте «Продукты» и внесите значения с известной упаковки на 100 г.
4. Нажмите «Добавить порцию в дневник», укажите массу и дату. Проверьте предпросмотр и подтвердите запись. Без подтверждения дневник не изменяется.

Устанавливать .NET SDK, Java, Android Studio или сервер на телефон не нужно. Сборка требует этих инструментов, запуск готового APK — нет. Минимальная версия приложения — Android 5.0 / API 21; фактическая совместимость зависит также от архитектуры процессора. Проверенный APK и поддерживаемые ABI перечисляются в отчёте сборки. Если старый телефон сообщает «приложение не установлено», сначала уточните его модель, версию Android и наличие предыдущей установки, а не удаляйте данные.

## Что работает без интернета

- отдельные профили с отдельными продуктами, блюдами, сессиями, дневником и целями;
- ручной ввод пищевой ценности с источником и качеством;
- создание собственного блюда из выбранных продуктов, исходных масс, явно удалённой массы и готового веса;
- повторное добавление порции сохранённого блюда;
- расчёт КБЖУ, обязательный предпросмотр и подтверждение;
- дневные цели, прогресс, исправление массы и удаление ошибочной записи;
- восстановление последнего незавершённого черновика после перезапуска.

На вкладке «Ввод» отдельно выбираются «Записать в дневник» и «Создать блюдо». Сохранение блюда не добавляет съеденную порцию автоматически. Все расчёты выполняет то же доменное C#-ядро, что использует сервер.

## Подключение Groq

1. Создайте личный API-ключ в [Groq Console](https://console.groq.com/keys). Не отправляйте ключ в чат и не добавляйте его в Git.
2. В NutriFlow выберите нужный профиль, откройте «Настройки», вставьте ключ и сохраните.
3. Имена моделей задаются отдельно для текста, изображений и речи. Используйте модели, доступные вашему аккаунту Groq: изображение требует vision-модели, аудио — модели транскрипции. При недоступности модели замените её имя в настройках, а не меняйте код.
4. На вкладке «Ввод» опишите приготовление или съеденное. Последующие сообщения уточняют тот же черновик. Проверьте состав и расчёт перед подтверждением.

Ключ хранится в `SecureStorage` телефона отдельно для каждого профиля. Он не входит в APK или SQLite. Внешние запросы идут непосредственно по HTTPS в Groq: введённое описание, выбранное фото или аудио покидает телефон. Локальные расчёты и дневник сеть не используют. Доступность сервиса, моделей и лимиты аккаунта не гарантируются приложением.

«Фото этикетки» позволяет выбрать изображение либо использовать камеру. Распознанные значения можно исправить; сохранение требует сверки с этикеткой и основы **на 100 г**. AI-ответ сам по себе не становится проверенной пищевой ценностью. Оригинал фото сохраняется внутри выбранного профиля.

«Голос / аудиофайл» записывает микрофон либо принимает файл и показывает редактируемую расшифровку. Текст нужно проверить перед добавлением в описание. Максимальный файл — 8 МиБ, запись ограничена по времени. Разрешения камеры и микрофона запрашиваются при использовании соответствующей функции.

Поиск штрихкода сначала использует локальный каталог, затем Open Food Facts. Сетевой ответ проверяется перед сохранением; его качество остаётся `Unknown`, пока нет дополнительной проверки. Неизвестный продукт нельзя заменить пищевой ценностью из памяти языковой модели: внесите известные данные с упаковки.

## Обновления и сохранность данных

APK подписывается постоянным личным Android-ключом из GitHub Secrets. Для обновления устанавливайте новую сборку **поверх** старой: идентификатор `com.nutriflow.app` и сертификат должны остаться прежними, номер версии — не уменьшаться. Не удаляйте приложение ради обновления: удаление приложения или очистка его данных удалит локальную базу, профили, фотографии и ключи.

Локальные профили разделяют данные, но не являются паролем или защитой от человека с разблокированным телефоном. Автоматический системный backup отключён; пользовательского экспорта и восстановления мобильной базы в этой версии нет. Не считайте телефон единственной надёжной копией незаменимых данных.

Закрытый ключ и Windows-защищённый пароль находятся в игнорируемом `.private/android-signing/`, вне очищаемых результатов сборки. Сохраните его приватную резервную копию; файл `password.dpapi` привязан к Windows-пользователю и сам по себе не подходит для переноса на другой компьютер. Не публикуйте этот каталог. Помощник подписи отказывается генерировать новый ключ при утрате локальной копии и уже существующих секретах репозитория. Секреты: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`.

## Проверка на своём телефоне

1. Создайте два профиля, добавьте продукт, цель и порцию только в первом; второй должен оставаться пустым.
2. Отключите интернет. Создайте блюдо вручную, подтвердите его, добавьте порцию, измените её массу и проверьте дневной итог.
3. Перезапустите приложение: выбранный профиль, продукты, блюдо и записи должны сохраниться.
4. Подключите ключ Groq в одном профиле. Проверьте текст, фото и речь отдельно; второй профиль не должен получать его ключ.
5. Установите следующее APK поверх текущего и повторно проверьте сохранность данных.

Автоматические тесты ядра и облачный эмулятор не заменяют эту приёмку на конкретном устройстве. Фактические результаты сборки и проверок записываются в [PROGRESS.md](PROGRESS.md).
