# Резервные копии NutriFlow

`NutriFlow.Tools` создаёт и проверяет парную копию SQLite и каталога фотографий. Это отдельная консольная утилита, не HTTP endpoint. Она не запускает API, не применяет миграции и не читает ключи AI. Автоматического восстановления, расписания и копирования в облако пока нет.

## Перед созданием

1. Остановите API и все другие программы, которые могут менять базу или фотографии.
2. Уточните фактические `Database:Path` и `Storage:LabelPhotosPath` своей установки. Утилита принимает явные пути; относительные пути считаются от текущей папки, а не от content root API.
3. Выберите новый, ещё не существующий каталог назначения. Он не должен пересекаться с фотографиями или занимать путь базы / её служебных файлов.

`--offline` подтверждает первое условие пользователем. Утилита не обнаруживает все процессы записи и не останавливает их. Сверка исходных файлов обнаруживает наблюдаемые изменения, но не превращает копирование файловой системы в атомарный online-снимок. Используйте локальную доверенную файловую систему; одновременное ручное изменение или переименование каталогов не поддерживается.

## Команды

Из корня репозитория при стандартных путях хранения:

```powershell
dotnet run --project NutriFlow.Tools -- backup --database NutriFlow.Api/data/nutriflow.db --photos NutriFlow.Api/data/label-photos --output NutriFlow.Api/data/backups/manual-20261005 --offline
```

Если этот каталог уже существует, выберите другое имя: существующая копия не заменяется. Пути с пробелами заключайте в кавычки.

Проверка ранее созданной копии:

```powershell
dotnet run --project NutriFlow.Tools -- verify --backup NutriFlow.Api/data/backups/manual-20261005
dotnet run --project NutriFlow.Tools -- --help
```

`verify` ничего не исправляет и не восстанавливает. Проверяемая копия также не должна изменяться другими программами во время проверки. Коды завершения: `0` — успех, `1` — ошибка операции, `2` — неверные аргументы, `130` — отмена через Ctrl+C.

## Состав копии

```text
manual-20261005/
├─ nutriflow.db
├─ label-photos/
│  └─ исходные файлы фотографий
└─ manifest.json
```

Manifest содержит версию формата `1`, время UTC и для каждого файла относительный путь, длину и SHA-256. Абсолютные исходные пути, конфигурация API и ключи в него не записываются. Сам manifest не является записью в своём списке файлов.

Копируется вся база, а не данные одного владельца. Сохраняются все обычные файлы корня каталога фото, в том числе старые незарегистрированные. Вложенные каталоги, символические ссылки, junction и неоднозначные по регистру имена отклоняются, а не молча пропускаются. Отсутствие каталога фото — ошибка; существующий пустой каталог допустим, если база не требует фотографий.

## Как сохраняется целостность

- База и имеющиеся `-wal`, `-shm`, `-journal` сначала копируются обычными файловыми потоками в собственный временный каталог. SQLite никогда не открывает оригинал: даже read-only WAL-база может затронуть служебные файлы. [Особенности SQLite WAL](https://www.sqlite.org/wal.html#read_only_databases).
- `SqliteConnection.BackupDatabase` собирает отдельный файл базы из временной копии с учётом зафиксированных WAL-данных. Итоговый файл переводится в `journal_mode=DELETE` и не зависит от соседних WAL-файлов. [Microsoft.Data.Sqlite BackupDatabase](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/backup).
- Проверяются `integrity_check`, `foreign_key_check` и наличие файлов из `LabelPhotos.FileName` и старых ссылок `Products.SourceReference` вида `label-photo:...`. Старой базе не добавляются таблицы и миграции.
- Сверяются перечень и контрольные суммы исходных файлов; фотографии проверяются также после копирования. Manifest записывается последним. Готовый каталог публикуется только после успешных проверок; ошибка или отмена не создаёт готовую копию. Удаляются только собственные временные каталоги утилиты. После аварийного завершения процесса каталог `.nutriflow-backup-<guid>.partial` может остаться; это не готовая копия.
- `verify` проверяет структуру, длины и SHA-256, отвергает лишние / отсутствующие файлы, повторяющиеся записи и небезопасные пути. Для проверки SQLite создаётся ещё одна временная копия, поэтому рядом с проверяемой базой не появляются служебные файлы. Максимальный размер manifest — 16 МиБ.

Итоговая SQLite может побайтно отличаться от исходной из-за сборки снимка и смены режима журнала. Сохранность проверяется содержимым базы, целостностью и ссылками, а не равенством SHA-256 двух разных представлений SQLite.

## Ограничения и безопасность

SHA-256 обнаруживает повреждение относительно manifest, но не доказывает доверенное происхождение: человек, изменивший данные и manifest вместе, может пересчитать суммы. Копия не зашифрована и содержит личные сообщения, дневник и изображения. Храните её с ограниченным доступом, не в `wwwroot` и не в публичном репозитории. Примерный путь `NutriFlow.Api/data/backups` исключён из Git вместе со всем `data`; при другом назначении проверьте исключения отдельно.

Копия на том же диске защищает от неудачного обновления, но не от потери диска. После проверки сохраните отдельный экземпляр на другом носителе. Проверка копии ещё не является испытанием восстановления и запуска API; безопасное восстановление будет отдельным шагом.
